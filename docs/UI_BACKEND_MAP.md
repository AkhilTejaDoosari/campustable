# Existing UI → backend responsibilities

Status: Phase 0B design map; operation names are domain operations, NOT a finalized HTTP API.

| UI area/control                    | Real operation / source of truth                                 | Who can act                                | Important refusal/failure                                            | Evidence IDs        |
| ---------------------------------- | ---------------------------------------------------------------- | ------------------------------------------ | -------------------------------------------------------------------- | ------------------- |
| Hero / How it works / Join         | Public static brand assets and routes                            | Anyone                                     | No fictional account selector in real app                            | UI-01               |
| Personal email / code              | Auth session and verification provider                           | Account claimant                           | Delivery failure, wrong/expired/reused proof; no fake login          | ID-01, ID-02        |
| Save and continue / restore        | Save/read setup draft in DB after auth                           | Owner                                      | Session expiry, stale revision, write failure                        | ID-03               |
| Role selector                      | Update selected role, invalidate incompatible status             | Owner; approval reviewer-only              | Browser role edit cannot confer approval                             | ID-04               |
| University email / code            | Request/consume affiliation proof; unique claim                  | Authenticated claimant                     | Unknown domain, duplicate ownership, concurrent claim                | ID-05, ID-06        |
| Unknown university fields          | Submit registry-review request                                   | Authenticated member                       | Pending review, unsafe supplied URL; no automated verified label     | ID-07               |
| Alumni fields / review evidence    | Save self-reported affiliation; optional later review            | Owner / scoped reviewer                    | Inactive school email allowed; sensitive uploads deferred until safe | ID-08               |
| Faculty directory/title/help       | Save role-review request; approve/reject                         | Owner submits, authorized reviewer decides | Mail verification alone cannot grant faculty status                  | ID-09               |
| Program/date calendar              | Save role-specific dates with server validation                  | Owner                                      | Impossible order/future alumni/past student date                     | PR-01               |
| Offered/wanted skills              | Store profile-topic relation/custom normalized topic             | Owner                                      | Input bounds, duplicate labels, unsafe text                          | PR-02               |
| Availability/meeting/timezone      | Persist participation preferences                                | Owner                                      | Unsupported enum/timezone, visibility leaks                          | PR-03               |
| Learning goal / project idea       | Save preference / owner-only project draft                       | Owner                                      | No auto-publication of incomplete brief                              | PJ-01               |
| Links / optional resume            | Save URL fields; upload/manage private object                    | Owner                                      | Unsafe URL, invalid/oversized file, cross-account download           | PR-04               |
| Profile visibility / completion    | Persist disclosure policy and validate completeness              | Owner                                      | Client cannot approve itself or expose private fields                | PR-05               |
| People / university/skills filters | Query permitted profile projection                               | Eligible member                            | No results, page failure; no hidden-field filtering leaks            | DS-01               |
| Profile detail / intro             | Read permitted fields; create single pair request                | Eligible viewer                            | Blocked/self/consumed pair / unavailable profile                     | CT-01               |
| Projects / university filter       | Query published project projection                               | Eligible member                            | No results, draft leakage                                            | PJ-02               |
| Create/save/publish project        | Create draft, update brief, publish with roles                   | Eligible owner                             | Invalid brief/non-owner/closed project                               | PJ-03               |
| Apply to role                      | Create structured application; contact request if first contact  | Eligible applicant                         | Full/ineligible/duplicate/blocked; no bypass of intro                | TM-01               |
| Accept / decline / withdraw        | Transactional lifecycle operations and actor-specific projection | Correct recipient/sender/role owner        | Stale state, decline leak, repeated-send loophole                    | CT-02, CT-03, TM-02 |
| Add Collaborator                   | Create invitation; membership only on acceptance                 | Project owner invites; invitee accepts     | No unilateral member enrollment                                      | TM-03               |
| Messages / send                    | Read permitted conversation; append idempotent message           | Accepted participants                      | Blocked/not participant; duplicate retry                             | MS-01, MS-02        |
| Progress / outcome                 | Persist authorized update / self-reported contribution           | Authorized actor                           | No fabricated replies, outcomes or team membership                   | TM-04               |
| Leave/remove/close                 | Membership/project state transition                              | Member leaves; owner removes/closes        | Owner departure, races and history retention                         | TM-05               |
| Block/report (missing in demo)     | Persist block/report, enforce restrictions, reviewer queue       | Member / authorized reviewer               | Unauthorized reviewer; continued contact after block                 | TR-01, TR-02        |
| Recruiter/talent/shortlist         | Deferred; no live routes/settings/API                            | None in V1                                 | Must not leak through hidden route or public hero                    | SC-01               |

UI copy/visual changes are limited to explicit runtime conversion, the recruiter exclusion, complete-brief additions, consent-based invitations and factual failure states. New authentication/recovery screens fit the same visual system. No changes to the archived reference HTML itself.
